# 可观测性与预警规范

## 这份文档是什么

可观测性就是让系统出问题时能看清楚发生了什么。

初学者可以这样理解：

- 日志 Logs：记录“发生了什么事”。
- 链路追踪 Traces：记录“一次请求经过了哪些步骤”。
- 指标 Metrics：记录“系统整体是否健康”。
- 预警 Alerts：当指标异常时提醒工程师。
- 看板 Dashboard：把关键状态用图表展示出来。

这几类能力合在一起，能帮助我们排查登录失败、消息发不出去、位置不上报、AI 超时、推送失败等问题。

## 总体方案

服务端统一使用：

- `ILogger` 结构化日志。
- OpenTelemetry Logs。
- OpenTelemetry Traces。
- OpenTelemetry Metrics。
- OTLP exporter。

默认可观测性组合：

- OpenTelemetry Collector：统一接收日志、Trace、Metric。
- Prometheus：保存指标。
- Grafana：展示看板。
- Loki：保存日志。
- Tempo：保存链路追踪。
- Alertmanager：发送预警。

这套方案不绑定某一家云厂商。后续如果接入商业 APM，也必须通过 OpenTelemetry 或适配层接入。

## 关联 ID

`correlation_id` 用来串起一次完整用户操作。

例如用户点击“发起 AI 分析”：

1. Android 生成 `correlation_id`。
2. 请求带到 `/ai`。
3. 服务端校验授权时继续使用。
4. 调用模型时继续使用。
5. 保存结果和发送通知时继续使用。

这样排查问题时，可以从一个 ID 找到完整链路。

## 结构化日志

日志必须使用结构化字段，不要把信息拼成一大段字符串。

推荐字段：

- `service_name`。
- `operation`。
- `correlation_id`。
- `trace_id`。
- `span_id`。
- `result`。
- `error_code`。
- `duration_ms`。

允许但必须脱敏：

- `user_id_hash`。
- `couple_id_hash`。
- `data_type`。
- `consent_version`。
- `model_id`。

禁止字段：

- 聊天原文。
- 完整经纬度。
- Wi-Fi 名称。
- 手机号。
- 验证码。
- token。
- prompt。
- 模型输入快照。

## Trace 规范

Trace 要覆盖关键链路。

服务端通用 span：

- 请求进入 API。
- 鉴权。
- 绑定关系校验。
- 授权校验。
- 数据库读写。
- 消息队列发布。
- 第三方服务调用。
- 响应返回。

AI 分析必须额外记录：

- `ai_privacy.load_binding`。
- `ai_privacy.load_consents`。
- `ai_privacy.build_prompt`。
- `ai_privacy.model_call`。
- `ai_privacy.save_result`。
- `ai_privacy.record_audit`。

这些 span 只能记录元数据，不能记录 prompt 或隐私原文。

## Metric 规范

首版必须准备这些指标：

- API 请求量。
- API 失败率。
- API p95 延迟。
- AI 分析成功数。
- AI 分析失败数。
- AI 模型超时数。
- AI 格式错误数。
- AI 不安全输出数。
- 位置上传成功率。
- 设备状态上传成功率。
- 消息发送成功率。
- RTC token 签发失败数。
- 厂商推送成功率。
- 授权撤回次数。
- 解绑次数。
- AI 结果过期清理数量。

指标名称必须稳定，不能随意改名。改名必须写 ADR 和变更记录。

## Alert 预警规则

首版预警建议：

- API 5xx 错误率 5 分钟内超过 2%。
- API p95 延迟 5 分钟内超过 2 秒。
- AI 模型超时率 10 分钟内超过 5%。
- AI 审计写入失败出现 1 次。
- AI 结果过期清理连续失败。
- 位置上传成功率 10 分钟内明显下降。
- 设备状态上传成功率 10 分钟内明显下降。
- 推送失败率 10 分钟内超过 10%。
- 数据库连接池耗尽。
- 消息队列积压持续增长。

预警必须能说明：

- 哪个服务。
- 哪个操作。
- 影响范围。
- 建议先看哪个 Dashboard 或 Trace。

## Dashboard 规范

Grafana 首版看板至少包含：

- 服务总览。
- API 请求量、错误率、延迟。
- AI 分析成功率、失败原因、模型耗时。
- 定位轨迹上传状态。
- 设备状态上传状态。
- 聊天和推送状态。
- 授权撤回和解绑趋势。

Dashboard 只展示元数据，不展示隐私原文。

## 本地开发

本地开发可以先只运行服务和测试。需要联调可观测性时，再启动 OpenTelemetry Collector、Prometheus、Grafana、Loki、Tempo、Alertmanager。

项目门禁命令：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Assert-ProjectGate.ps1
```
